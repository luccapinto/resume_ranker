## Contexto
Um ATS tradicional obriga o recrutador a traduzir a própria intenção para filtros: abrir a vaga, marcar senioridade, digitar competência, ordenar coluna. A intenção real ("quem são os três melhores para a vaga de SRE e por quê?") é uma frase, não um formulário.

O risco óbvio de uma interface conversacional sobre dados de contratação é a alucinação: um modelo que inventa um candidato, um score ou um motivo é pior do que nenhuma interface.

## Objetivo
Construir um copiloto que converse em português, execute ações reais no ATS e seja incapaz de inventar dados — porque não tem acesso a nenhum dado que não venha de uma ferramenta executada em Python.

## Especificação Técnica

### Contrato
O modelo não recebe o banco. Ele recebe um catálogo de ferramentas e um preâmbulo de contexto (vagas existentes com id, título e status; total de candidatos; vaga em foco na tela). Toda informação concreta chega por resultado de ferramenta.

Ferramentas expostas:

| Ferramenta | O que faz |
|---|---|
| `listar_vagas` | Vagas com o funil de cada uma |
| `ranquear_candidatos` | Busca híbrida + reranking para uma vaga, com filtros rígidos |
| `buscar_candidatos` | Busca semântica livre no banco de talentos |
| `detalhar_candidato` | Perfil completo e candidaturas |
| `explicar_match` | Análise com evidências citadas e verificadas |
| `mover_candidatura` | Move alguém de etapa no funil |
| `resumo_pipeline` | Números agregados do ATS |
| `auditar_vies` | Auditoria contrafactual do par candidato/vaga |

### Cards
Cada ferramenta devolve **dois** artefatos: um `digest` compacto que volta para o modelo como mensagem `tool`, e um `card` estruturado que o frontend renderiza. O ranking vira lista ordenada com score e aderência; a auditoria vira o relatório de equidade; o resumo vira o funil.

Isso resolve a tensão entre conversa e densidade de informação: o modelo escreve duas frases sobre os dois primeiros colocados, e a interface mostra a lista inteira em formato visual. O prompt instrui explicitamente a não repetir a tabela em texto.

### Laço de execução
Até 5 rodadas de tool calling por turno. Se o limite for atingido, uma última chamada sem ferramentas força a resposta com o que já foi apurado — o usuário nunca fica sem resposta.

Falhas são reportadas ao modelo, não escondidas: ferramenta inexistente, argumento inválido ou exceção viram `{"erro": "..."}` na mensagem `tool`, e o modelo se explica ao recrutador.

### Restrições de conduta
O prompt de sistema proíbe comentar gênero, idade, aparência ou origem. Perguntas nesse sentido são respondidas explicando o desenho do sistema e oferecendo a auditoria de viés.

### Rastreabilidade
O turno inteiro é um trace: cada rodada do modelo é um span `llm`, cada execução de ferramenta é um span `tool` com entrada e saída. A interface mostra as ferramentas usadas como badges e um link direto para a cascata de execução.

## Critérios de Aceite
- [x] Perguntar pelos melhores candidatos de uma vaga executa `ranquear_candidatos` e renderiza o card de ranking.
- [x] O modelo nunca recebe dados que não vieram de uma ferramenta.
- [x] Ferramenta inexistente ou com erro não derruba o turno.
- [x] Argumentos JSON malformados degradam para os valores padrão.
- [x] O laço termina mesmo se o modelo insistir em chamar ferramentas.
- [x] As badges de ferramenta e o `trace_id` aparecem na interface.
